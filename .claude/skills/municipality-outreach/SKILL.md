# 自治体被リンク打診フロー

`docs/municipality_outreach_list.csv`(93件、都道府県/自治体名/ドメイン/生存確認/
連絡手段/連絡先URL/情報元ページ/備考の8列)を対象に、`docs/templates/` の
テンプレートを使って被リンクを打診する。**メール送信・フォーム送信は取り消せない
外部向けアクション**なので、この作業全体を通じて一括送信は絶対に行わない。

## 着手前に必ず確認すること

1. **返信先メールアドレスが未確定**: メールテンプレートの署名欄が
   `Email: (※ 運営側で取得後に追記)` のままになっている(独自ドメイン未取得、
   [[project_domain_decision]])。実際に送信する前に、個人アドレスを使うのか、
   専用アドレスを用意するのかをユーザーに確認する。ここが未解決のまま送信しない
2. **送信ステータス管理列がCSVに無い**: 送信日・返信有無・結果を記録する列が
   存在しない。送信を始める前に、CSVへの列追加か別ファイルでの進捗記録の
   方式をユーザーと決める

## 送信フロー(1件ずつ)

1. CSVから対象を1件選ぶ。「連絡手段」列でメール/フォームを判定する
   - メール → `backlink-request-municipal-email.md`(詳細版、掲載実績・透明性
     ページ・撤去窓口を明記)
   - フォーム → `backlink-request-municipal-form.md`(文字数上限に応じて
     220字版/100字版を選ぶ)
2. 送信前チェックリストを実施する:
   - CSV記載内容(自治体名・ドメイン等)の正誤確認
   - 掲載実績(その自治体の動物がoneco上に実在表示されているか)の実在確認
   - 生存確認(サイトがまだ稼働しているか)の再確認
   - フォームの場合は文字数上限・URL貼付制限・reCAPTCHA等の自動化不可な
     仕組みが無いかの確認
3. **ここで必ずユーザーに送信内容を提示し、明示的な承認を得てから送信する**
4. 送信後、CSV(または合意した記録先)に送信日・結果を記録する
5. 1件送ったら、数日は次を送らず反応(返信・開封・迷惑メール判定等)を見る。
   これはCLAUDE.mdの「一括処理は必ず1件で試してから全件実行」の原則そのもの
6. 反応が良好であれば、ユーザーと相談の上で次のバッチ件数を決めて2に戻る。
   一度に大量送信しない

## やってはいけないこと

- ユーザーの承認なしに送信する
- CSVの全件、または未承認の複数件を一度に送信する
- 返信先メールアドレスが未確定のまま送信する
- 送信記録を残さず次の対象に進む
